Repeating-key XOR — finding the key length

The first step in breaking repeating-key (Vigenère) XOR is guessing the key's length. The claimed tool for that is the Hamming distance (the number of differing bits between two byte strings). This page lets you experiment with why that works — poke at it and see if you can explain the pattern before reading any explanation.

The answer

Reveal: why Hamming distance finds the key length (open only after you've tried)

At the correct keysize, the two bytes in a column were encrypted with the same key byte. XOR-ing them cancels the key:

c1 ⊕ c2 = (p1 ⊕ k) ⊕ (p2 ⊕ k)
        = p1 ⊕ p2 ⊕ (k ⊕ k)
        = p1 ⊕ p2            (because k ⊕ k = 0)

So you are really XOR-ing two English letters. English letters cluster in a narrow byte range (lowercase a–z all share the high bits 011xxxxx), so p1 ⊕ p2 has few 1-bits → low Hamming distance.

At a wrong keysize, the two bytes used different key bytes, so the key does not cancel:

c1 ⊕ c2 = p1 ⊕ p2 ⊕ (kA ⊕ kB)

Now kA ⊕ kB is a nonzero constant that scrambles the result toward random → more 1-bits → higher Hamming distance.

Dividing by K makes different keysizes comparable; averaging over many block pairs smooths the noise so the true keysize's dip stands out. Its multiples dip too, because they are also key-aligned.
